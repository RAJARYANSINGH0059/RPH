## Data model (apps/api/app/models)

users · cases · case_memberships · victim_claims · claim_transaction_links · funds_records · cooperation_packs · source_files (sha256, kind, status) · parse_runs (mapping, warnings, stats) · evidence_items (raw_value, normalised_value, source_locator, extraction_method, parser version, event/valid time + precision, observed_at, ingested_at, quality_flags) · transactions (paise, raw strings, direction, channel, duplicate_of) · entities (typed, unique per case) · relationships (type, evidence_level, valid_from/to, observed_at, method + version, heuristic_score, limitations, review_status) · relationship_evidence · counter_evidence · analyst_reviews · audit_events (append-only) · synthetic_scenarios (public manifest + opaque sealed ref) · benchmark_runs.

## Relationship semantics

| Evidence level | Produced by |
|---|---|
| directly_observed | statement rows, document mentions, DNS/hosting observations |
| corroborated | same (reference, amount) in two statements; identifier seen in a document and a statement |
| derived | SAME_ACCOUNT_IDENTIFIER (reference+amount bridge), BELONGS_TO_DOMAIN |
| candidate | SHARED_INFRASTRUCTURE (shared IP/CDN), SIMILAR_NAME |
| stale | DNS/hosting observation outside the transaction window ±30 days |

Shared IP/CDN/ASN never produces COMMON_OPERATOR; the only way to obtain one is the benchmark-only `safeguards=False` mode.

## Request flow for an upload

1. size check → magic-bytes kind detection (extension mismatch flagged) → SHA-256 → random storage key
2. SourceFile + ParseRun rows; parser dispatch by kind
3. per row/block: EvidenceItem (raw + normalised + locator) → Transaction / Entity / directly-observed Relationship
4. `rules.rebuild_derived` recomputes derived edges and counter-evidence (idempotent)
5. audit event; response carries the parser preview and warnings

The synthetic factory calls step 1–5 through the same `ingest_upload` function with the generated bytes.

## Digital-twin increment (2026-11-22)

- **Standard analytical contract** (`services/contract.py`): every new analysis returns `findings` (kind, statement, evidence class, evidence refs), `uncertainties`, `counter_evidence`, `limitations`, `warnings`, `human_review_required`, `provenance` and a `result_id` hash, so pages, PDFs and the replay can treat them uniformly.
- **Twin layer**: `InvestigationEvent` rows (observed / reported / derived / unresolved, with layer and validity) are built from transactions, payment instructions, documents, infrastructure observations, role claims and investigation actions; `twin.assemble` renders them as-of any moment and `replay` diffs two moments.
- **Payment bridge**: `parsers/qr.py` decodes images (OpenCV) and parses `upi://` payloads; `services/payment_bridge.py` persists `PaymentInstruction` rows and matches them to statement rows by identifier, amount, reference and time tolerance, emitting `INSTRUCTS_PAYMENT_TO` / `PAYMENT_INSTRUCTION_MATCHES_TRANSACTION` relationships with method `payment_bridge`.
- **Bounded flow**: `services/bounded_flow.py` builds a joint LP across the path accounts that have statements (scipy HiGHS) and reports min/max per hop; see `BOUNDED_FUND_ATTRIBUTION_SPEC.md`.
- **Proof**: `services/proof.py` builds the manifest; `scripts/verify_proof.py` re-derives it with the standard library only; see `PROOF_CERTIFICATE_SPEC.md`.
- **Browser session**: Next.js route handlers under `apps/web/app/api/` act as a BFF. `/api/session/demo|login|logout` exchange credentials for an HttpOnly cookie; `/api/proxy/[...path]` forwards API calls with the bearer token; direct uploads/downloads use 10-minute scoped tokens from `/api/auth/short-token`. The API remains bearer-token based and stateless.
- **Demo isolation**: `Role.demo_analyst` principals (`User.is_demo`, `expires_at`) are created by `POST /api/auth/demo-session` (origin check, per-IP limit); `core/deps.py` restricts them to synthetic cases and rejects expired tokens; expired demo workspaces are purged on the next demo request.
- **Navigation**: `apps/web/lib/nav.ts` is the single registry (groups → children with `hrefFor(caseId)`); `scripts/check-nav.mjs` fails CI on duplicate destinations or routes without a page.
- **Package and baseline**: `services/package.py` assembles the proof-carrying investigation package (refusing any entry that would contain sealed-truth keys); `services/baseline.py` is the graph-only comparison baseline used by the benchmark and, after a locked submission, by the blind-challenge reveal (`synthetic/challenge.compare_with_truth`).
- **Evidence-request responses**: `POST /requests/{id}/response` links an already-uploaded case file to a request; `dependencies.advance_request` appends the response to the status history, and the dependency map exposes `partial` requirements with their unresolved remainder.
